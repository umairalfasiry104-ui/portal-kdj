## 1. Root cause

The original `public.kdj_prepare_booking_approval` accepted a parseable date/time and created a `PREPARED` approval without checking the existing Scheduling V2 calendar. The Bot could therefore send a customer-visible approval summary for a time that the final booking transaction would later reject.

The final `public.kdj_create_booking` already enforced these policies, but enforcement occurred too late in the customer journey.

## 2. Minimal correction

The PREPARE RPC now preflights the same existing policy before inserting an approval row or allowing the Bot to send a summary:

- WhatsApp booking must be at least one calendar day ahead in `Asia/Jakarta` (requested local date must be later than today's local date).
- Consultation weekday must be Monday–Friday (ISO weekday 1–5).
- Consultation must start at or after 09:00 WIB and finish by 17:00 WIB; duration stays 120 minutes, so latest start is 15:00 WIB.
- Existing active bookings are checked using the same half-open 150-minute interval (120-minute consultation + 30-minute buffer) as Scheduling V2.
- If the slot conflicts, PREPARE returns `SLOT_UNAVAILABLE` and up to three alternatives from the existing `kdj_find_booking_alternatives` function.

The check is a preflight only; it does not reserve or lock the slot. `kdj_create_booking` remains the authoritative transactional check at finalization, protecting against a slot being taken after PREPARE.

No business rule, API signature, table schema, or booking duration was expanded. Existing `SECURITY DEFINER`, empty `search_path`, and service_role-only EXECUTE grants are preserved.

## 3. Bot response handling

Updated local Bot source:
- `lib/booking/customer-approval-service.js`: deterministic PREPARE policy results are returned as scheduling outcomes; the session does not incorrectly enter an ambiguous reconciliation state.
- `lib/booking/conversation-scheduling.js`: H-1, closed-day, and working-hours rejections ask the customer for a new date/time; slot conflict moves to the existing alternatives selection flow.
- `scripts/test-booking-approval-flow.mjs`: added regression coverage for no-summary-on-closed-day and customer-facing closed-day/slot-alternative handling.

Ambiguous provider/RPC outcomes continue to fail closed and use the existing reconciliation flow. No automatic summary resend or booking is introduced.
